# Dataset Documentation

## PaySim

PaySim is a synthetic mobile-money transaction dataset generated by the PaySim simulator. The simulator uses aggregated information from private real transaction logs to generate data resembling normal mobile-money operations and inject simulated malicious behavior.

The commonly distributed Kaggle file contains approximately 6.36 million rows, 11 columns and 744 hourly time steps.

### Original fields

| Field | Meaning |
|---|---|
| step | Simulation time step; one step represents one hour |
| type | CASH-IN, CASH-OUT, DEBIT, PAYMENT or TRANSFER |
| amount | Transaction amount |
| nameOrig | Originating customer identifier |
| oldbalanceOrg | Originator balance before transaction |
| newbalanceOrig | Originator balance after transaction |
| nameDest | Destination identifier |
| oldbalanceDest | Destination balance before transaction |
| newbalanceDest | Destination balance after transaction |
| isFraud | Simulated fraud label |
| isFlaggedFraud | Simulator flag |

### Fraud label

`isFraud` is the supervised target for the baseline evaluation.

### Leakage caution

The dataset documentation notes that fraud transactions are cancelled and recommends caution with balance columns. The project therefore makes leakage checks explicit in `train_baseline.py` and reports the feature set used.

### Graph enrichment

PaySim does not directly supply observed device/location information in the required schema. The project therefore creates deterministic synthetic enrichment:
- `Device`: derived from customer identifier hash
- `Location`: derived from customer identifier hash and time step
- `Merchant`: destination identifiers beginning with `M`

The enrichment is for graph demonstration and must be described as synthetic.

### Why this is suitable

It supports:
- transaction-level fraud evaluation
- sender/recipient graph construction
- temporal analysis
- transaction-type analysis
- suspicious account connectivity
- path/cycle analysis
- graph centrality
- community/ring exploration
