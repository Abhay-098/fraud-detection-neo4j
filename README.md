## Dataset statement

The primary dataset is PaySim, a synthetic mobile-money transaction dataset generated by the PaySim simulator using aggregated information from private real transaction logs. It is **not real customer banking data**. The distributed Kaggle file contains approximately 6.36 million transactions over 744 hourly steps (30 simulated days).

Source:
https://www.kaggle.com/datasets/ealaxi/paysim1

The raw PaySim file is intentionally NOT bundled into this ZIP because the public CSV is roughly 494 MB. Instead, use `scripts/download_paysim.py` or download it manually and place it at:

`data/raw/PS_20174392719_1491204439457_log.csv`

## Important modeling choice

PaySim provides customer/recipient identifiers and transaction information, but it does not directly provide all entities from the Review 1 conceptual model such as device, location and merchant attributes in the desired graph form.

Therefore this project:
1. Loads the original PaySim transaction fields without changing their meaning.
2. Maps customer identifiers to Customer and Account nodes for graph representation.
3. Creates deterministic **synthetic enrichment** for Device and Location relationships.
4. Represents `M...` destination identifiers as Merchant nodes.
5. Clearly labels the enrichment as synthetic in the documentation.

The synthetic enrichment is used only to demonstrate relationship-aware graph analysis. It must not be presented as observed device/location data from PaySim.

## Graph model

```text
(Customer)-[:OWNS]->(Account)
(Customer)-[:USES]->(Device)
(Account)-[:ACCESSED_FROM]->(Device)
(Account)-[:PERFORMS]->(Transaction)
(Transaction)-[:SENT_TO]->(Account)
(Transaction)-[:PAID_TO]->(Merchant)
(Transaction)-[:OCCURRED_AT]->(Location)
```

## Quick start

### 1. Install

Python 3.10+ is recommended.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

### 2. Configure Neo4j

Copy `.env.example` to `.env` and set:

```text
NEO4J_URI=bolt://localhost:7687
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=your_password
NEO4J_DATABASE=neo4j
```

Neo4j Desktop is sufficient for a student demonstration.

### 3. Get PaySim

Option A — download from Kaggle:
https://www.kaggle.com/datasets/ealaxi/paysim1

Place the CSV in `data/raw/`.

Option B — use the downloader script if you have Kaggle API credentials:

```bash
python scripts/download_paysim.py
```

Option C — immediate demo without the large dataset:

```bash
python scripts/generate_demo_dataset.py --rows 25000
```

The demo data is synthetic and is NOT the PaySim dataset.

### 4. Prepare data

For real PaySim:

```bash
python scripts/prepare_paysim.py --input data/raw/PS_20174392719_1491204439457_log.csv --rows 250000
```

For the demo dataset:

```bash
python scripts/prepare_paysim.py --input data/demo/paysim_demo.csv --rows 25000 --demo
```

### 5. Generate plots and evaluation

```bash
python scripts/run_analysis.py --input data/processed/paysim_subset.csv
```

Outputs go to:
- `reports/figures/`
- `reports/metrics.json`
- `reports/evaluation.csv`

### 6. Load Neo4j

```bash
python scripts/load_neo4j.py --input data/processed/paysim_subset.csv
```

The importer uses batched transactions so that a large subset can be loaded without constructing the entire graph in memory.

### 7. Start API

```bash
uvicorn backend.main:app --reload
```

Open:
- Dashboard: http://127.0.0.1:8000/
- Swagger API docs: http://127.0.0.1:8000/docs
- Health: http://127.0.0.1:8000/api/health

### 8. Optional baseline ML evaluation

```bash
python scripts/train_baseline.py --input data/processed/paysim_subset.csv
```

This is a baseline, not the central contribution. For an imbalanced fraud dataset, report precision, recall, F1 and PR-AUC alongside accuracy.

## Final-review fraud detection upgrade

The v3 API adds explainable transaction-risk analysis and candidate fraud-ring detection. The risk score intentionally does **not** use PaySim's `is_fraud` label; that label remains ground truth for evaluation.

- `POST /api/fraud/analyze` — analyze a hypothetical/new transaction using amount, account history, shared-device exposure, transaction activity/type, and reverse-flow graph evidence.
- `GET /api/fraud/analyze/{transaction_id}` — analyze an existing graph transaction and return its PaySim label separately as ground truth.
- `GET /api/fraud/rings` — candidate coordinated groups based on shared-device membership plus internal money flows.
- `GET /api/fraud/cycles` — explicit three-account circular money-flow patterns.

Risk scores are investigation indicators, not proof of fraud. High-risk results should be reviewed by an investigator.
